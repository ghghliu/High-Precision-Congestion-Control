# 400G 2-tier non-blocking fat-tree benches

Fabric (all links 400Gbps, 1µs):

```
4 leaf × 2 spine, no oversubscription
each leaf: 16 host downlinks + 8 uplinks to each spine  (16:16 = 1:1)
hosts 0..63, leaves 64..67, spines 68..69
```

Generate / refresh `mix/ft2_*.txt` and flow files:

```bash
python3 simulation/scripts/gen_fattree_400g.py
```

Run all CCs (config is generated by `run.py`, no hand-written config):

```bash
cd simulation
bash scripts/run_ft_400g.sh
```

Compares `--cc pfc|dcqcn|hp|timely`. `--cc pfc` sets `ENABLE_QCN 0`.

## Why only a subset of hosts

The topology always has 64 NICs so the fabric is 1:1. Workloads use a few racks/hosts to keep the causal story readable and the sim cheap:

| Case | Hosts used | What it shows |
|------|------------|----------------|
| `ft_pair2` | 2 senders leaf0 → 2 dests leaf1 | Parallel uplinks actually ECMP; each flow ~400G |
| `ft_hol` | 16 incast @ t=2.0s, remote victim probes @ t+300µs | dest-leaf HoL (ECMP spray) |
| `ft_outcast4` / `ft_outcast8` | N:1 incast + **same-NIC** victim to another dest | **PFC outcast**: victim throttled to ~1/N |
| `ft_incast8` | 8:1 onto one dest | **DCQCN slow recovery** after CNP, bottleneck left idle |
| `ft_incast16` | 16:1 | Same, larger incast degree (trend) |
| `ft_probe_{32k..20m}` | 8:1 incast already running + mouse joins same dest | **CC under-throughput vs size**: sub-RTT mice finish before CNP; few-RTT mice cut and finish unconverged; large mice recover |

## Outcast (source HoL)

```
leaf0 hosts 0..N-1  ----N:1---->  leaf1 dest C
leaf0 host 0        ----1:1---->  leaf2 dest V   (idle rack)
```

Host 0 has two QPs on PG 3. PFC pauses the whole PG on that NIC, so the flow to V is backpressured even though V is idle — goodput ≈ 400G/N.

Run just this case:

```bash
cd simulation
bash scripts/run_outcast_400g.sh
```

Mouse joining an already-running incast (size sweep, FCT / slowdown / PFC / CC rate):

```bash
cd simulation
bash scripts/run_probe_400g.sh
```

See `docs/probe_results_400g.md`.

## Expected signatures

- **PFC:** high dest utilization, many pause events; **outcast victim on the incast source NIC falls to ~1/N**. Probe mice wait a ~250µs pause floor (32k slowdown 28×) and amortize toward ~54G on 20MB.
- **DCQCN:** victim stays near line rate (no NIC pause), but incast aggregate goodput ≪ 400G (AI=80Mb/s, RP_TIMER=300µs). A mouse joining that incast: no `mlx_dec` if it finishes before the first CNP (~37µs / ≲400KB); 1–2MB die during MD at 1–8G; 5–20MB recover after FR at ~449µs (slowdown saturates ~5.6×).
- **HPCC:** INT window, little/no PFC, faster recovery than DCQCN. Probe cut starts at one RTT (+8µs) but 32k is already done (slowdown 1.07).
- **TIMELY:** delay-based; typically avoids host-0 pause but can still under-utilize vs HPCC. Small probes look PFC-like; 20MB stays near 240G.
